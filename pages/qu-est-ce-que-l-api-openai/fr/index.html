Qu'est-ce que l'API OpenAI ?

Réponse courte

L'API OpenAI est une interface de programmation qui permet d'intégrer les modèles d'intelligence artificielle d'OpenAI dans un site, une application ou un logiciel. Elle permet de générer du texte, analyser des documents, créer des images, traiter de l'audio et automatiser des tâches.

Qu'est-ce que l'API OpenAI ?

L'API OpenAI est une interface de programmation qui permet aux développeurs d'utiliser les modèles d'intelligence artificielle d'OpenAI dans leurs propres applications, sites web ou logiciels.

  • Elle sert de passerelle entre votre application et les modèles OpenAI.
  • Elle permet d'envoyer une demande, par exemple une question ou une consigne, puis de recevoir une réponse générée par l'IA.
  • Elle fonctionne généralement via des requêtes HTTP authentifiées par une clé API.
  • Elle peut être utilisée pour créer des chatbots, générer du contenu, résumer des documents, analyser des données ou automatiser des tâches.
  • Contrairement à ChatGPT, l'API ne fournit pas d'interface prête à l'emploi : elle est destinée à une intégration technique.

Comment obtenir une clé API OpenAI ?

Pour obtenir une clé API OpenAI, créez un compte sur la plateforme OpenAI, accédez à la gestion de votre organisation, créez ou sélectionnez un projet, puis générez une clé secrète dans la rubrique API Keys.

  • Connectez-vous à la plateforme OpenAI.
  • Accédez aux paramètres de votre organisation.
  • Créez un projet ou sélectionnez un projet existant.
  • Ouvrez la rubrique API Keys du projet.
  • Cliquez sur « Create new secret key ».
  • Copiez immédiatement la clé et enregistrez-la dans un gestionnaire de mots de passe, un coffre-fort de secrets ou une variable d'environnement sécurisée.
  • Attribuez à la clé les permissions les plus limitées possibles selon l'usage prévu.

OpenAI indique que la clé secrète ne peut plus être consultée après sa création. Si vous la perdez, vous devez en générer une nouvelle et mettre à jour votre application.

  • Chaque projet possède ses propres clés API.
  • Une clé peut avoir des permissions « All », « Restricted » ou « Read Only ».
  • Pour une intégration professionnelle, privilégiez une clé restreinte plutôt qu'une clé avec tous les droits.
  • Ne stockez jamais la clé directement dans le code source, dans un fichier public ou dans une application mobile.
  • Utilisez de préférence une variable d'environnement côté serveur ou un service de gestion des secrets.

Avant de mettre l'intégration en production, testez la clé avec une requête simple, vérifiez les limites de débit de votre projet et configurez un suivi des dépenses.

Quelle est la différence entre ChatGPT et l'API OpenAI ?

ChatGPT est une application prête à l'emploi destinée aux utilisateurs, tandis que l'API OpenAI est une interface destinée aux développeurs pour intégrer les modèles d'OpenAI dans leurs propres sites, applications ou logiciels.

  • ChatGPT s'utilise directement dans une interface de conversation.
  • L'API OpenAI s'utilise depuis un site, une application mobile, un logiciel ou un système automatisé.
  • ChatGPT convient à la rédaction, à la recherche, au brainstorming ou à l'assistance quotidienne.
  • L'API convient à la création d'un chatbot client, d'un assistant interne, d'un outil de génération de contenu ou d'une automatisation.
  • Avec l'API, l'entreprise garde davantage de contrôle sur l'expérience utilisateur, les données envoyées, les modèles appelés et l'intégration dans ses outils.
  • La facturation de l'API est distincte de l'abonnement ChatGPT.

En pratique, une entreprise peut utiliser ChatGPT pour ses équipes et l'API OpenAI pour proposer une fonctionnalité IA à ses clients, automatiser un processus ou connecter l'IA à son CRM, son site e-commerce ou son logiciel interne.

L'API OpenAI est-elle payante ?

Oui, l'utilisation de l'API OpenAI est généralement payante. Pour démarrer une utilisation payante, ajoutez un moyen de paiement dans les paramètres de facturation de votre compte API. Cette facturation est distincte de votre abonnement ChatGPT.

  • Le coût dépend principalement du modèle choisi, des fonctionnalités utilisées et du volume de tokens consommés.
  • Les tokens d'entrée correspondent aux éléments envoyés au modèle dans la requête.
  • Les tokens de sortie correspondent aux éléments générés par le modèle dans la réponse.
  • Les tokens mis en cache peuvent bénéficier d'un tarif différent grâce au prompt caching.
  • Pour certains modèles de raisonnement, les tokens de raisonnement ne sont pas visibles dans la réponse, mais comptent dans l'usage de sortie.
  • L'utilisation d'outils, de stockage ou de certaines fonctionnalités spécifiques peut entraîner une facturation distincte.

Un token peut représenter un caractère, une partie de mot, un mot entier ou un signe de ponctuation. Il ne correspond donc pas exactement à un mot.

Pour maîtriser le budget, définissez un budget mensuel, activez des seuils d'alerte, surveillez la consommation dans le tableau de bord OpenAI et limitez les appels inutiles. OpenAI recommande notamment de fixer plusieurs seuils de dépense, par exemple à 90 % et 95 % d'un budget mensuel.

Les limites de débit existent également. Elles peuvent être exprimées en requêtes par minute, tokens par minute, requêtes par jour ou tokens par jour, selon le modèle et le niveau d'utilisation. Elles sont définies au niveau de l'organisation et du projet, et non au niveau de chaque utilisateur.

Comment sécuriser une clé API OpenAI ?

Pour sécuriser une clé API OpenAI, ne la partagez jamais publiquement, stockez-la dans une variable d'environnement ou un gestionnaire de secrets, attribuez-lui des permissions limitées, surveillez son usage et révoquez-la immédiatement en cas de fuite.

  • Ne publiez jamais la clé dans un dépôt GitHub, GitLab, un forum, une documentation publique, un e-mail ou une capture d'écran.
  • Ne l'intégrez pas directement dans le code d'une application mobile, d'un site public ou d'un fichier JavaScript accessible côté navigateur.
  • Stockez la clé dans une variable d'environnement côté serveur ou dans un service de gestion des secrets.
  • Attribuez à chaque clé les permissions minimales nécessaires.
  • Créez une clé distincte par projet, par environnement ou par application afin de limiter l'impact en cas de compromission.
  • Surveillez régulièrement l'usage et les coûts afin de détecter une activité anormale.
  • Définissez des limites de dépenses et des seuils d'alerte.
  • Renouvelez périodiquement les clés en supprimant les anciennes et en créant de nouvelles clés.
  • Vérifiez le code avant de le pousser dans un dépôt public afin de vous assurer qu'aucune clé n'a été incluse.
  • Soyez prudent avec les outils, bibliothèques et plateformes tierces qui demandent l'accès à votre clé API.

Si une clé a été exposée, supprimez-la immédiatement depuis le tableau de bord OpenAI, créez-en une nouvelle, mettez à jour votre application et examinez l'historique d'utilisation pour repérer une activité inhabituelle.

L'API OpenAI utilise une authentification Bearer : la clé est transmise dans l'en-tête HTTP Authorization. Elle doit être chargée depuis une variable d'environnement ou un service de gestion des secrets sur le serveur, et non depuis le code côté client.
